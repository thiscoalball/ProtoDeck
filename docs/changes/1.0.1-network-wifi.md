# ProtoDeck 1.0.1 — Network and Wi-Fi enhancement record

Status: **In development**  
Baseline: **ProtoDeck 1.0.0**  
Target: **ProtoDeck 1.0.1**

This document records the user-visible changes planned for the 1.0.1 update after the 1.0.0
baseline. The development manifest is `1.0.1+1`: pull-request and manual artifacts use the 1.0.1
version with a Debug build label, while a `v1.0.1` tag produces the 1.0.1 Release label.

Checked items mean the source implementation is present. Platform-specific runtime verification and
Release artifact generation remain part of the release gate; a checked item does not claim that every
driver, adapter or Linux distribution has already been tested.

## Scope

### Desktop address configuration

- [x] Windows and Linux can switch an eligible adapter between DHCP and static IPv4/DNS.
- [x] The adapter selector exposes interface name, description, MAC address, state, current address,
  link speed, route priority and default-route status so Ethernet, Wi-Fi, VPN and virtual adapters
  are not confused.
- [x] Static-address application performs an active ARP/neighbor conflict probe. A suspected conflict
  is an explicit overrideable warning; a silent Ping result is never treated as proof that an
  address is free.
- [x] Before applying, ProtoDeck compares DHCP/static mode, IPv4/prefix, gateway, DNS, interface
  metric and static routes with the live configuration.
- [x] Writing and connectivity are separate result stages. Only a failed or mismatched write rolls
  back automatically. Link, gateway, DNS and Internet warnings never roll back the written address
  and can be checked again after upstream equipment becomes ready.
- [x] The live configuration is re-read field by field after applying, including DHCP state,
  address/prefix, gateway, DNS, route interface, metric and the Windows network profile. Delayed DHCP
  observations are shown as warnings rather than write failures.
- [x] One independent pre-change restore point is retained for manual “restore previous
  configuration”, even when the new configuration was written successfully.
- [x] A configuration can be saved as a reusable non-secret template. Templates support exact-name,
  MAC and default-transport adapter matching, route/metric and diagnostic preferences, one-click
  apply, search, duplicate, rename, delete and JSON import/export.
- [x] Android remains read-only and does not display static-IP controls.

### Wi-Fi discovery and connection

- [x] Nearby networks are grouped by SSID while preserving each BSSID as an independently inspectable
  radio.
- [x] Search covers SSID, BSSID and security; signal/security/width filters and sort state remain
  restorable.
- [x] Android uses a user-approved system network flow, Linux uses NetworkManager, and Windows can
  activate an already-saved WLAN profile without reading its password.
- [x] Local-only connectivity is treated as a valid result rather than an Internet failure.
- [x] Unsupported bands and connection actions are hidden by runtime capability, not locale.

### Wi-Fi radio analysis

- [x] Each BSSID exposes signal, band, channel, width, standard, security, observation timestamp and
  only those beacon capabilities the platform actually reports.
- [x] Per-BSSID signal timelines retain real samples, preserve throttled/cached gaps and support
  comparison without fabricating periodic values.
- [x] Channel scoring includes RSSI, frequency overlap, reported width and available BSS-load data;
  recommendations explain their inputs and confidence.
- [x] 6 GHz UI appears only when the platform supports it or an actual 6 GHz result exists.

### Wi-Fi quality, roaming and security

- [x] Current-link quality correlates RSSI with gateway reachability/latency, DNS latency and Internet or
  local-only state.
- [x] Connection verification records address acquisition, default route, gateway, DNS, IPv4/IPv6,
  captive portal and reachability evidence.
- [x] Roaming sessions record BSSID changes, before/after RSSI, channel/band changes, lost probes and
  the observed recovery window.
- [x] Security inspection identifies open/legacy/transition configurations and suspicious same-SSID
  inconsistencies as evidence-based warnings, never as proof of an attack.
- [x] Android RTT appears only for a device and AP that expose FTM support. Easy Connect and
  local-only hotspot actions remain hidden until an end-to-end implementation exists; none are simulated.

## Platform delivery

| Capability | Android | Windows | Linux |
|---|---|---|---|
| Read current link and nearby APs | Native | WLAN system snapshot | NetworkManager |
| Connect to Wi-Fi | User-approved system flow | Saved WLAN profiles | NetworkManager |
| Static IPv4/DNS | Hidden/read-only | Supported with elevation | Supported through NetworkManager/Polkit |
| Per-BSSID signal history | Scan cadence limited | System snapshot cadence | NetworkManager scan cadence |
| RTT / DPP / local-only hotspot | Capability-gated | Hidden unless implemented | Hidden unless implemented |

## Explicitly excluded

- Importing floor plans, manual survey points and Wi-Fi heatmaps.
- Claims of raw RF spectrum, non-Wi-Fi interference, noise floor or SNR when the platform does not
  expose those measurements.
- Silent Android Wi-Fi/static-IP changes, root-only behavior and fabricated success states.

## Verification target

- Flutter analysis and focused tests for models, scoring, templates, stale samples and roaming.
- Full Dart tests.
- Android Release APK and Linux Release bundle on the current Linux host.
- Windows source compatibility is maintained; the Windows Release bundle remains a Windows runner or
  GitHub Actions build because Flutter does not cross-compile a Windows desktop executable on Linux.
